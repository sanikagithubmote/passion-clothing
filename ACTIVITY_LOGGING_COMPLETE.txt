===============================================================================
                        API ENDPOINT DETAILS
===============================================================================

Endpoint: GET /api/sales/dashboard/recent-activities

Parameters:
  - limit (default: 10) - Number of activities to return
  - offset (default: 0) - Pagination offset
  - department (optional) - Filter by department (e.g., "procurement")

Example Request:
  GET /api/sales/dashboard/recent-activities?limit=10&offset=0&department=procurement

Example Response:
{
  "activities": [
    {
      "id": 1,
      "type": "purchase_order_created",
      "title": "Purchase Order Created: PO-20251115-00001",
      "message": "Purchase Order PO-20251115-00001 has been created...",
      "department": "procurement",
      "order_number": "PO-20251115-00001",
      "amount": "45000.00",
      "created_at": "2025-11-15T14:32:00.000Z"
    }
  ],
  "pagination": {
    "total": 50,
    "limit": 10,
    "offset": 0,
    "pages": 5
  }
}

===============================================================================
                        DATABASE SCHEMA
===============================================================================

Table: activities

Columns:
  - id (INT, PK, AI)           : Unique identifier
  - type (ENUM)                 : Activity type
  - title (VARCHAR)             : Short title
  - message (LONGTEXT)          : Detailed message
  - department (ENUM)           : Department
  - order_number (VARCHAR)      : Related order number
  - related_entity_id (INT)     : Entity ID
  - related_entity_type (VARCHAR) : Entity type
  - amount (DECIMAL)            : Financial amount
  - created_by (INT)            : User ID
  - metadata (JSON)             : Additional context
  - created_at (TIMESTAMP)      : Creation time
  - updated_at (TIMESTAMP)      : Update time

Indexes:
  ✅ created_at              (for recent activities query)
  ✅ type                    (for filtering)
  ✅ department              (for department-specific views)
  ✅ order_number            (for order tracking)
  ✅ (entity_type, entity_id) (for entity tracking)

===============================================================================
                        COMMON QUESTIONS
===============================================================================

Q: Does this slow down the application?
A: No! Activity logging is async and non-blocking.

Q: What if activity logging fails?
A: Main operation succeeds anyway. Logging errors are silent.

Q: Can I see who created the PO?
A: Yes! created_by field stores user ID. Can add more context in metadata.

Q: How long are activities stored?
A: Forever! Archive old activities if needed.

Q: Can I log other events?
A: Yes! Use the ActivityService methods or create new ones.

Q: Will this work with my existing dashboards?
A: Yes! Completely backward compatible.
